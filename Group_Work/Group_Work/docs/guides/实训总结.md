## 二、遇到的主要问题

### 1. 🚫 技术难点问题

#### 问题1：JSON字段映射处理
**具体表现**: MyBatis无法直接映射JSON字段到Java对象
```java
// 数据库字段: image_urls JSON类型
// Java实体: private String imageUrls;
```
**困难程度**: ⭐⭐⭐⭐
**影响范围**: 产品管理模块的所有JSON字段

#### 问题2：前后端字段名不一致
**具体表现**: 数据库下划线命名与Java驼峰命名不匹配
```
数据库: star_rating, check_in_time
Java:   starRating, checkInTime
```
**困难程度**: ⭐⭐⭐
**影响范围**: 整个实体映射层

#### 问题3：用户认证状态管理
**具体表现**: `authStore.setUser is not a function` 错误
```javascript
// 错误调用了不存在的方法
authStore.setUser(user)
authStore.setToken(token)
```
**困难程度**: ⭐⭐⭐⭐⭐
**影响范围**: 整个用户认证流程

#### 问题4：复杂的订单状态流转
**具体表现**: 订单状态变更逻辑复杂，容易出现状态不一致
```
PENDING → CONFIRMED → COMPLETED
       ↘ CANCELLED
```
**困难程度**: ⭐⭐⭐⭐
**影响范围**: 订单管理核心业务

### 2. 🤔 业务理解问题

#### 问题5：数据库设计权衡
**困难点**: 在规范化和性能之间找平衡
- 是否使用JSON字段存储复杂数据？
- 如何设计索引既保证查询性能又节省存储空间？
- 外键约束的使用场景和限制？

#### 问题6：用户权限设计
**困难点**: 设计灵活且安全的权限系统
- 如何区分普通用户和管理员权限？
- 如何实现细粒度的功能权限控制？
- 如何保证权限验证的安全性？

## 三、解决方案与学习过程

### 1. 💡 技术问题解决

#### 解决方案1：自定义TypeHandler
```java
// 创建JSON字段处理器
@MappedJdbcTypes(JdbcType.VARCHAR)
@MappedTypes({List.class})
public class JsonListTypeHandler extends BaseTypeHandler<List<String>> {
    private static final ObjectMapper mapper = new ObjectMapper();
    // 实现JSON与Java对象的双向转换
}
```
**学习收获**: 理解了MyBatis的扩展机制，学会了自定义类型处理器

#### 解决方案2：统一状态管理
```javascript
// 重构认证逻辑，使用store统一管理
const userData = await authStore.login(form.email, form.password)
// 添加向后兼容的方法
const setUser = (userData) => {
  user.value = userData
  isLoggedIn.value = true
  localStorage.setItem('user', JSON.stringify(userData))
}
```
**学习收获**: 掌握了Vue3状态管理的最佳实践，理解了单一数据源原则

#### 解决方案3：数据库索引优化
```sql
-- 设计复合索引优化查询
CREATE INDEX idx_products_search ON products(type, city, status, price);
CREATE INDEX idx_orders_user_time ON orders(user_id, status, created_at);
-- 使用全文索引支持中文搜索
FULLTEXT INDEX ft_title_desc (title, description)
```
**学习收获**: 学会了根据业务场景设计高效的数据库索引

## 四、深度感悟与反思

### 1. 🌟 技术成长感悟

#### 从理论到实践的跨越
> **感悟**: 课堂学习和实际项目开发存在巨大差距

在课堂上学习Vue、Spring Boot时，每个技术点都能理解，但当需要将它们整合成一个完整系统时，发现了很多意想不到的挑战。比如前后端数据传输的格式转换、状态管理的复杂性、数据库性能优化等问题，都需要在实践中不断摸索和学习。

**最大收获**: 学会了如何在复杂系统中定位和解决问题，这种解决实际问题的能力是课本无法教授的。

#### 系统思维的重要性
> **感悟**: 技术不是孤立存在的，需要系统化思考

开发这个项目让我深刻理解了系统思维的重要性。一个看似简单的用户登录功能，实际涉及前端表单验证、后端身份认证、数据库用户管理、状态持久化、权限控制等多个环节。任何一个环节出问题，都会影响整个功能的正常运行。

**最大收获**: 学会了从整体架构的角度思考问题，而不是只关注单个技术点。

### 2. 🎯 项目管理感悟

#### 需求理解的深度
> **感悟**: 表面简单的需求往往隐藏着复杂的业务逻辑

最初看到"旅游推荐平台"这个需求时，觉得相对简单，就是展示目的地和酒店信息。但深入分析后发现，涉及用户权限管理、复杂的产品分类、订单状态流转、支付集成、数据统计分析等众多复杂业务场景。

**最大收获**: 学会了需求分析的方法，能够从业务角度思考技术实现方案。

#### 代码质量的重要性
> **感悟**: 好的代码是写给人看的，不只是给机器执行的

在项目后期维护和功能扩展时，发现早期代码质量对开发效率的巨大影响。清晰的命名、详细的注释、合理的架构设计，能够大大提高开发效率和降低维护成本。

**最大收获**: 培养了编写高质量代码的意识和能力。

### 3. 🚀 能力提升感悟

#### 学习能力的提升
> **感悟**: 技术更新很快，学习能力比具体技术更重要

在项目开发过程中，经常遇到新的技术问题需要快速学习。比如MySQL 8.0的JSON字段特性、Vue 3的Composition API、TypeScript的高级类型等。这个过程锻炼了我快速学习新技术的能力。

**最大收获**: 掌握了高效学习技术的方法，能够快速适应技术栈的变化。

#### 解决问题的思路
> **感悟**: 解决问题的过程比结果更有价值

每次遇到技术难题时，通过系统化的分析、查找资料、尝试方案、验证结果的过程，不仅解决了当前问题，更重要的是培养了解决复杂问题的思维模式。

**最大收获**: 形成了结构化的问题解决思路，提高了面对未知问题的信心。

### 4. 🎓 未来发展思考

#### 技术深度 vs 技术广度
> **思考**: 如何在技术深度和广度之间找到平衡？

通过这个全栈项目，我接触了前端、后端、数据库等多个技术领域，但也意识到每个领域都有很深的技术内容需要学习。未来需要在保持技术广度的同时，选择1-2个方向进行深度钻研。

#### 业务理解能力
> **思考**: 技术服务于业务，如何提高业务理解能力？

在项目开发过程中，发现技术实现相对容易，但理解业务需求、设计合理的解决方案是更大的挑战。未来需要更多关注业务逻辑，培养从业务角度思考技术方案的能力。

#### 团队协作能力
> **思考**: 如何在团队开发中发挥更大价值？

虽然这次主要是个人开发，但在实际工作中肯定需要团队协作。需要学习如何在团队中进行技术沟通、代码协作、知识分享等能力。
