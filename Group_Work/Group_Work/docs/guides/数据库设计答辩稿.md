# Plan Your Escape 旅游网站 - 数据库设计答辩稿

## 一、项目介绍

大家好，我负责"Plan Your Escape"旅游网站的数据库设计和部分后端接口开发。本项目采用MySQL数据库，设计了完整的用户、产品、订单管理系统，支持多角色权限控制和复杂业务逻辑。

### 技术选型
- **数据库**: MySQL 8.0
- **设计工具**: MySQL Workbench
- **ORM框架**: MyBatis Plus
- **数据类型**: 使用JSON类型存储复杂数据

## 二、数据库整体设计

### 1. 设计原则
- **规范化设计**: 遵循第三范式，减少数据冗余
- **性能优化**: 合理使用索引和分区
- **可扩展性**: 预留扩展字段，支持业务发展
- **数据完整性**: 使用外键约束保证数据一致性

### 2. 核心表结构
```
users (用户表)
  ├── products (产品表)
  │     └── orders (订单表) 
  ├── destinations (目的地表)
  └── user_favorites (收藏表)
```

## 三、详细表结构设计

### 1. 用户表 (users)
```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
    username VARCHAR(50) UNIQUE NOT NULL COMMENT '用户名',
    email VARCHAR(100) UNIQUE NOT NULL COMMENT '邮箱',
    password VARCHAR(255) NOT NULL COMMENT '密码(BCrypt加密)',
    full_name VARCHAR(100) COMMENT '真实姓名',
    phone VARCHAR(20) COMMENT '手机号',
    avatar_url VARCHAR(500) COMMENT '头像URL',
    birthday DATE COMMENT '生日',
    role ENUM('USER', 'ADMIN') DEFAULT 'USER' COMMENT '用户角色',
    status ENUM('ACTIVE', 'INACTIVE', 'BANNED') DEFAULT 'ACTIVE' COMMENT '账户状态',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    
    -- 索引
    INDEX idx_email (email),
    INDEX idx_username (username),
    INDEX idx_role_status (role, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

**设计要点**:
- 用户名和邮箱都设置唯一索引，支持两种登录方式
- 密码使用BCrypt加密存储，长度255字符
- 角色和状态使用ENUM类型，提高查询效率
- 预留avatar_url、birthday等扩展字段

### 2. 产品表 (products)
```sql
CREATE TABLE products (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '产品ID',
    title VARCHAR(200) NOT NULL COMMENT '产品标题',
    description TEXT COMMENT '产品描述',
    price DECIMAL(10,2) NOT NULL COMMENT '价格',
    type ENUM('HOTEL', 'TOUR') NOT NULL COMMENT '产品类型',
    city VARCHAR(100) COMMENT '城市',
    country VARCHAR(100) COMMENT '国家',
    region VARCHAR(100) COMMENT '地区',
    
    -- JSON字段存储复杂数据
    image_urls JSON COMMENT '图片URL列表',
    facilities JSON COMMENT '设施列表',
    features JSON COMMENT '特色功能',
    
    -- 酒店专用字段
    star_rating INT COMMENT '星级评分(1-5)',
    address TEXT COMMENT '详细地址',
    
    -- 旅游产品专用字段
    duration VARCHAR(50) COMMENT '行程天数',
    difficulty_level ENUM('EASY', 'MEDIUM', 'HARD') COMMENT '难度等级',
    
    -- 通用字段
    rating DECIMAL(3,2) DEFAULT 0.00 COMMENT '用户评分',
    review_count INT DEFAULT 0 COMMENT '评价数量',
    view_count INT DEFAULT 0 COMMENT '浏览次数',
    status ENUM('ACTIVE', 'INACTIVE', 'DRAFT') DEFAULT 'ACTIVE' COMMENT '产品状态',
    
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    -- 索引设计
    INDEX idx_type_city (type, city),
    INDEX idx_country_region (country, region),
    INDEX idx_price (price),
    INDEX idx_rating (rating),
    INDEX idx_status (status),
    FULLTEXT KEY ft_title_desc (title, description)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='产品表';
```

**设计亮点**:
- 使用JSON字段存储图片列表和设施信息，灵活性强
- 支持HOTEL和TOUR两种产品类型，预留了专用字段
- 全文索引支持标题和描述的模糊搜索
- 复合索引优化常用查询组合

### 3. 订单表 (orders)
```sql
CREATE TABLE orders (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '订单ID',
    order_no VARCHAR(32) UNIQUE NOT NULL COMMENT '订单号',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    product_id BIGINT NOT NULL COMMENT '产品ID',
    
    -- 订单基础信息
    departure_date DATE COMMENT '出发日期',
    return_date DATE COMMENT '返回日期',
    travelers INT DEFAULT 1 COMMENT '出行人数',
    total_amount DECIMAL(10,2) NOT NULL COMMENT '订单总金额',
    
    -- 订单状态管理
    status ENUM('PENDING', 'CONFIRMED', 'COMPLETED', 'CANCELLED') DEFAULT 'PENDING' COMMENT '订单状态',
    payment_status ENUM('UNPAID', 'PAID', 'REFUNDED') DEFAULT 'UNPAID' COMMENT '支付状态',
    
    -- 联系人信息
    contact_name VARCHAR(100) NOT NULL COMMENT '联系人姓名',
    contact_phone VARCHAR(20) NOT NULL COMMENT '联系人电话',
    contact_email VARCHAR(100) NOT NULL COMMENT '联系人邮箱',
    special_requests TEXT COMMENT '特殊要求',
    
    -- 时间字段
    confirmed_at TIMESTAMP NULL COMMENT '确认时间',
    completed_at TIMESTAMP NULL COMMENT '完成时间',
    cancelled_at TIMESTAMP NULL COMMENT '取消时间',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    -- 外键约束
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE RESTRICT,
    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE RESTRICT,
    
    -- 索引设计
    INDEX idx_user_status (user_id, status),
    INDEX idx_product_id (product_id),
    INDEX idx_order_no (order_no),
    INDEX idx_status_payment (status, payment_status),
    INDEX idx_departure_date (departure_date),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';
```

**设计特色**:
- 订单号使用32位唯一字符串，便于业务处理
- 详细的状态管理：订单状态+支付状态
- 记录关键操作的时间戳，便于业务分析
- 外键约束使用RESTRICT，防止误删关联数据

## 四、索引优化策略

### 1. 主键索引
- 所有表都使用自增BIGINT作为主键
- 确保查询和关联的高效性

### 2. 唯一索引
```sql
-- 用户表
ALTER TABLE users ADD UNIQUE INDEX uk_username (username);
ALTER TABLE users ADD UNIQUE INDEX uk_email (email);

-- 订单表
ALTER TABLE orders ADD UNIQUE INDEX uk_order_no (order_no);
```

### 3. 复合索引
```sql
-- 优化常见查询组合
CREATE INDEX idx_products_search ON products(type, city, status, price);
CREATE INDEX idx_orders_user_time ON orders(user_id, status, created_at);
CREATE INDEX idx_products_location ON products(country, region, type);
```

### 4. 全文索引
```sql
-- 支持中文搜索
ALTER TABLE products ADD FULLTEXT(title, description);
ALTER TABLE destinations ADD FULLTEXT(name, description);
```

## 五、数据完整性设计

### 1. 约束设计
```sql
-- 检查约束
ALTER TABLE products ADD CONSTRAINT chk_price CHECK (price > 0);
ALTER TABLE orders ADD CONSTRAINT chk_travelers CHECK (travelers > 0);
ALTER TABLE products ADD CONSTRAINT chk_rating CHECK (rating >= 0 AND rating <= 5);

-- 外键约束
ALTER TABLE orders 
ADD CONSTRAINT fk_orders_user 
FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE RESTRICT;

ALTER TABLE orders 
ADD CONSTRAINT fk_orders_product 
FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE RESTRICT;
```

### 2. 触发器设计
```sql
-- 自动生成订单号
DELIMITER $$
CREATE TRIGGER tr_orders_before_insert 
BEFORE INSERT ON orders
FOR EACH ROW
BEGIN
    IF NEW.order_no IS NULL OR NEW.order_no = '' THEN
        SET NEW.order_no = CONCAT('ORD', DATE_FORMAT(NOW(), '%Y%m%d'), 
                                  LPAD(LAST_INSERT_ID(), 8, '0'));
    END IF;
END$$
DELIMITER ;

-- 更新产品统计信息
DELIMITER $$
CREATE TRIGGER tr_update_product_stats
AFTER INSERT ON orders
FOR EACH ROW
BEGIN
    UPDATE products 
    SET view_count = view_count + 1 
    WHERE id = NEW.product_id;
END$$
DELIMITER ;
```

### 1. 分区策略

ALTER TABLE orders PARTITION BY RANGE (YEAR(created_at)) (

### 2. 查询优化
```sql
-- 优化常用查询
-- 1. 用户订单查询
EXPLAIN SELECT o.*, p.title, p.type 
FROM orders o 
JOIN products p ON o.product_id = p.id 
WHERE o.user_id = ? AND o.status = 'CONFIRMED'
ORDER BY o.created_at DESC;

-- 2. 产品搜索查询
EXPLAIN SELECT * FROM products 
WHERE type = 'HOTEL' 
  AND city = '北京' 
  AND status = 'ACTIVE' 
  AND price BETWEEN 100 AND 500
ORDER BY rating DESC, price ASC;
```

## 八、开发中遇到的问题与解决方案

### 1. JSON字段处理
**问题**: MyBatis无法直接映射JSON字段
**解决方案**: 
```java
// 自定义TypeHandler
@MappedJdbcTypes(JdbcType.VARCHAR)
@MappedTypes({List.class})
public class JsonListTypeHandler extends BaseTypeHandler<List<String>> {
    private static final ObjectMapper mapper = new ObjectMapper();
    
    @Override
    public void setNonNullParameter(PreparedStatement ps, int i, List<String> parameter, JdbcType jdbcType) throws SQLException {
        try {
            ps.setString(i, mapper.writeValueAsString(parameter));
        } catch (JsonProcessingException e) {
            throw new SQLException("Error converting List to JSON", e);
        }
    }
}
```

### 2. 数据库字段映射
**问题**: 前端字段名与数据库字段名不一致
**解决方案**: 
```xml
<!-- MyBatis ResultMap映射 -->
<resultMap id="ProductResultMap" type="Product">
    <id column="id" property="id"/>
    <result column="title" property="name"/>
    <result column="image_urls" property="imageUrls" typeHandler="JsonListTypeHandler"/>
    <result column="facilities" property="facilities" typeHandler="JsonListTypeHandler"/>
</resultMap>
```

### 3. 订单状态管理
**问题**: 复杂的订单状态流转
**解决方案**:
