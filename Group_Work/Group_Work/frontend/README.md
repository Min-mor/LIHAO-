# 3. 设计理念
本项目的设计理念基于以下核心原则：

- **优雅的极简主义美学**：注重内容与功能的完美平衡
- **清新柔和的渐变配色**：与品牌色系浑然一体
- **恰到好处的留白设计**：提升内容可读性
- **轻盈通透的沉浸式体验**：让用户专注于内容
- **信息层级清晰**：通过微妙的阴影过渡与模块化卡片布局
- **精心打磨的细节**：包括圆角、微交互和视觉比例

# 4. 设计规范
本项目采用了 `uni-app` 进行多端开发，以下为暂定的设计

## 一、 Wot-UI （组件库）

采用 [Wot-UI](https://wot-ui.cn/) 作为组件库的主要原因有：
- 首先是设计风格契合本项目的轻量化、现代化和简约化，在视觉上弥补了 `uni-app` 无法使用 vue 的原生组件的困境。
- 同时由于它是为 `uni-app` 量身打造的，可以确保在 App、小程序、H5 等多端拥有一致且稳定的表现。
- 支持按需加载，不会使得应用程序变得臃肿，同样也支持主题定制，可以根据需求调整颜色、字体等基础样式。

## 五、 样式策略
- **组件样式**：组件内部样式在 .vue 文件的 `<style lang="scss" scoped> `块中定义，确保样式的局部作用域，避免全局污染。

# 5. 开发规范

## (一). 代码规范

- 命名：
	- 组件文件名：使用大驼峰命名法，如 ProductCard.vue。
    - 变量/函数名：使用小驼峰命名法，如 getUserInfo。
- 语法：
    - 全面使用 Vue 3 的 `<script setup>` 语法。
    - 使用 ESLint 和 Prettier 工具强制执行统一的代码风格。
    - Props 定义：组件的 props 必须有明确的 TypeScript 类型定义，并尽可能提供默认值。

## (二). 组件规范

- 单一职责：每个组件只做一件事，并把它做好。避免创建庞大而臃肿的“万能组件”。
- 接口清晰：通过 props 接收数据，通过 emits 触发事件，与父组件进行通信。
- 内容分发：对于需要灵活插入内容的场景，优先使用 slots。
- 复用性：当某个UI片段在两个或以上的地方出现时，就应考虑将其抽象为可复用组件，存放在 `src/components/` 目录下。

## （三）. 状态管理规范

- 本地状态：组件内部的、不与其它组件共享的状态，直接使用 Vue 3 的 ref 或 reactive。
- 全局状态：跨页面、跨组件共享的状态，统一使用 Pinia 进行管理。在 src/store/ 目录下按业务模块创建独立的 store。

## （四）. API 请求规范

- 统一管理：在 `src/api/` 目录下创建API请求模块。建议使用 axios 或 uni.request 的封装版本，统一处理请求头、响应拦截、错误处理等。
- 前端业务逻辑：
	- 订单逻辑：严格遵循 “逻辑分离，独立预订” 模式。路线和酒店的预订是两个独立的流程。
	- 12306逻辑：遵循 “查询+跳转” 模式，前端负责展示车次信息，点击预订时跳转至外部官方渠道。
- 类型定义：为所有API的请求参数和响应数据创建 TypeScript 接口或类型，确保数据类型的安全。

# （五）. 错误处理与用户反馈

- API 错误：在API请求的封装层统一捕获网络异常、超时、服务器错误等，并进行上报或提示。
- 用户反馈：对于用户的操作结果，必须给出明确的视觉反馈。统一使用 Wot-UI 的 wd-toast (轻提示) 或 wd-message-box (模态对话框) 组件，保持体验一致。
- 加载与空状态：数据加载时应显示骨架屏  或加载动画，数据为空时应显示清晰的空状态提示页面。
